`summarizeFrames(ms: readonly number[]): FrameSummary`:

- `n = ms.length`; se `n === 0`, devolve tudo 0.
- `avgMs` = média; `avgFps = 1000 / avgMs`.
- `k = Math.max(1, Math.floor(n / 100))`. Use `n / 100`, não `n * 0.01`.
- `low1Fps = 1000 / (média dos k maiores)`; `maxMs` = o maior.

`validateBenchReport(r: BenchReport): string[]` produz os problemas nesta ordem e com **estes textos exatos** (`id` = `` `${run.scene}/${run.quality}` ``):

1. `r.schema !== BENCH_SCHEMA` → `schema: esperado nitro-crew-bench/1, veio ${String(r.schema)}`.
2. Para cada cena × qualidade de `r.options` sem run correspondente → `falta ${cena}/${q}`.
3. Para cada run:
   1. Cada campo de `frames, avgFps, low1Fps, avgMs, maxMs, calls, triangles, maxCalls, maxTriangles` que não passe em `Number.isFinite(x) && x > 0` → `${id}: ${campo} inválido (${String(x)})`.
   2. Só se `avgFps` e `low1Fps` forem finitos e `low1Fps > avgFps` → `${id}: 1% low ${low1Fps} acima da média ${avgFps}`.
   3. `!Array.isArray(run.viewports)` → `${id}: viewports ausente`, e **pula** os itens 4–7 deste run.
   4. `viewports.length !== humans` → `${id}: ${len} viewports para ${humans} jogadores`, e **pula** os itens 5–7.
   5. Em cada viewport `j`, todo campo de `BenchViewport` tem de passar em `Number.isFinite(x) && x >= 0`. Aqui é `>= 0`, porque na baixa e na média `samples`, `passes` e `postPx` são 0. Senão → `${id}: viewport ${j} ${campo} inválido (${String(x)})`.
   6. `targetPx !== targetW * targetH` → `${id}: viewport ${j} targetPx ${targetPx} ≠ ${targetW}×${targetH}`.
   7. Soma dos `viewports[].calls` ≠ `calls` → `${id}: chamadas ${calls} ≠ soma dos viewports ${soma}`. O mesmo para triângulos → `${id}: triângulos ${triangles} ≠ soma dos viewports ${soma}`.
